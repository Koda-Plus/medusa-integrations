# Subiekt nexo integration: verified facts

What the plugin and the bridge rely on, where each fact was checked, and what could not be confirmed. Checked on 2026-10-05 and 2026-10-06 unless a line says otherwise. Anything not listed here is our own design (the bridge contract in `contract/openapi.yaml`), not a fact about a third party.

## InsERT: product, licence, SDK

- **Sfera is part of Subiekt nexo PRO.** The Subiekt nexo PRO description lists it under "Dodatkowe rozwiązania dostępne w wersji PRO" as "Sfera dla Subiekta nexo: możliwość tworzenia własnych rozwiązań", with the technical documentation in the nexo SDK and a download link to it. Plain Subiekt nexo does not list it. Source: https://www.insert.com.pl/programy_dla_firm/sprzedaz/subiekt_nexo_pro/opis.html
- **The nexo SDK download** linked from that page: https://ftp.insert.com.pl/pub/demo/InsERT_nexo/nexoSDK.exe (installs to `C:\InsERT\nexoSDK\Bin\nexoSDK_<version>`, one folder per version; checked on a machine with 60.0.0.9195 and 61.0.1.9371 installed side by side).
- **No separate purchase or activation for Sfera in PRO.** The PRO page lists it as part of the PRO version and links the SDK as a plain download; InsERT documents an activation only for Sfera PRO+ ("Aktywacja Sfery PRO+ została opisana w artykule e-Pomocy technicznej"). The guide therefore says an active Subiekt nexo PRO licence is enough. Sources: the two pages above and below.
- **Sfera PRO+ is a different, separate module** ("Moduł Sfera PRO+ wchodzi w skład Pakietu PRO+"): event sphere (sfera zdarzeniowa) and spherical menu (menu sferyczne) inside the nexo programs. The bridge does not need it. Sources: https://www.insert.com.pl/dla_uzytkownikow/e-pomoc_techniczna/13594.html and https://www.insert.com.pl/programy_dla_firm/insert_nexo/nexo_pro_plus/sfera.html
- **Not confirmed: how a Sfera login counts against workstation licences.** No official InsERT page we found states it; the forum thread "Sfera a licencja" (https://forum.insert.com.pl/index.php?/topic/1978-sfera-a-licencja/) does not answer it. The setup guide therefore tells the store to confirm it with its InsERT partner instead of stating a rule.

## nexo SDK (Sfera) members the bridge uses

Verified against nexo SDK 61.0.1.9371 itself: the shipped examples (`Przyklady\PrzykladyRealizacjiDokumentow`, `PrzykladyKartoteki`, `PrzykladyCenniki`, `PrzykladyKsef`, `FakturowanieWydan`, `RealizacjaZamowieniaOdKlientaDoDokumentuSprzedazy`), the XML documentation next to the assemblies, and the assemblies' metadata read with `System.Reflection.MetadataLoadContext` (nothing executed against a database). The bridge compiles against these assemblies; a member that did not exist would not compile.

- **Version coupling.** Sfera connects only to a database of exactly its own version; a mismatch fails the login with a message containing "innej wersji". The bridge turns it into `subiekt_unavailable` with the fix (install the matching SDK, rebuild). A successful login therefore proves the SDK and database versions are equal, which is how `/v1/health` reports `database_version`. The SDK version is read from the SDK folder name (`nexoSDK_61.0.1.9371`), because the DLL file versions all say 1.0.0.0.
- **Connection.** `DanePolaczenia.Jawne(serwer, baza, autentykacjaWindowsDoSerwera: true)`, `new MenedzerPolaczen().Polacz(dane, ProductId.Subiekt, null)`, `Uchwyt.ZalogujOperatora(operator, haslo)`. Windows authentication to SQL Server: the service account needs access to the nexo database.
- **Licence state.** A used up trial or an expired licence surfaces as an exception whose message contains "Limit czasu pracy" (or a licence exception type): the bridge reports `licence: "refused"`; a successful login reports `"ok"`.
- **Contractors by NIP.** `Uchwyt.Podmioty().Dane.Wszystkie(p => p.NIP == nip)`, then `NIPSformatowany` (with dashes) and the `PL` prefix as fallbacks; several matches: the active one with the lowest id. New company: `Podmioty().UtworzFirme()`, `AutoSymbol()`, `Dane.NazwaSkrocona` (40), `Dane.Firma.Nazwa` (250), `Dane.NIPSformatowany`, address through `DodajAdres(TypyAdresu().DaneDomyslne.Glowny)` with `Szczegoly.Ulica/NrDomu/NrLokalu/KodPocztowy/Miejscowosc` and `Panstwa().DaneDomyslne.PL` (other countries by `KodPanstwaUE`, Greece is `EL`), e-mail and phone as `Kontakt` with `RodzajeKontaktu().DaneDomyslne.Email/Telefon`, then `Zapisz()`.
- **Sales documents.** `Uchwyt.DokumentySprzedazy().UtworzFaktureSprzedazy()` (FS) or `.UtworzParagon()` (PA); `WypelnijNaPodstawieWZ(wz[], wz[0], ParametryGrupowaniaDS)` when the order has WZ documents (the goods already left; realizing the ZK would move stock again), else `WypelnijNaPodstawieZK(...)`, as in the SDK examples. `ParametryGrupowaniaDS.MetodaPrzenoszeniaUwag = NiePrzenos` keeps the ZK notes (customer contact data) off the invoice; the bridge writes its own note with the order tag. The bridge never fiscalizes a paragon: Subiekt does, on its fiscal printer.
- **KSeF numbers.** `Uchwyt.DokumentyElektroniczne().Dane` rows with `DokumentPowiazanyId` = the sales document and a non-empty `NumerKSeF` (the e-invoice Subiekt generated and sent); else `Dokument.NumerKSeFDokumentu.Numer` (a number typed in by hand). Right after `Zapisz()` the bridge also reads `ObslugaKSeF.WygenerowanaEFaktura.NumerKSeF` when present. A KSeF number appears only after Subiekt sent the e-invoice, so the bridge watches FS documents without one for `Documents:KsefWatchDays` (default 30) and publishes `document.updated` when it appears.
- **Prices.** `Uchwyt.Cenniki().Dane.Wszystkie(c => c.Bazowy && c.Status == 1 && c.PoziomCen != null)`: approved (`Status` 1, Zatwierdzony) base price lists, one per price level (`PoziomCen.Symbol`, `Nazwa`, currency from `Waluta.Symbol` of the list or the level). Per product the main position (`PozycjaCennika.Glowna`) with `CenaNetto` and `CenaBrutto`.
- **Products.** `Asortymenty().Dane` limited to the kinds `RodzajeAsortymentu().DaneDomyslne.Towar/Komplet/Usluga`; EAN from `PodstawowaJednostkaMiaryAsortymentu.PodstawowyKodKreskowy.Kod`; unit from `JednostkaSprzedazy.JednostkaMiary.Symbol`; weight from the basic unit (`Masa` with `JednostkaMiaryMasy.Symbol`, converted to kg); sales VAT from `StawkaVatSprzedaz` (`Stawka` is a fraction, 0.23; `Zwolniona`, `NiePodlegaOpodatkowaniu`); the "Sklep internetowy" flag (`SklepInternetowy`) becomes `active`, the products meant for the online shop.
- **Stock, ZK, WZ, cancel marker, header fields**: unchanged since 0.1.0 and documented there (same SDK checks).

## KSeF

- A KSeF number is the unique number KSeF assigns to an invoice ("Numer KSeF to unikalny numer, który identyfikuje fakturę w Krajowym Systemie e-Faktur"). The official page details the 35 character collective identifier (`9999999999-IZ202602-FFFFFFFFFFFF-FF`) but not the structure of an invoice's KSeF number. The plugin and the bridge therefore treat the invoice KSeF number as an opaque string: stored and shown as Subiekt reports it, never parsed or validated. The demo builds numbers in the commonly cited shape (seller NIP, date, 12 characters, 2 control characters) only to look realistic. Source: https://ksef.podatki.gov.pl/informacje-ogolne-ksef-20/numer-ksef-i-zbiorczy-identyfikator/

## NIP

- Ten digits; the last is a check digit: multiply the first nine by the weights 6, 5, 7, 2, 3, 4, 5, 6, 7, sum, take the remainder modulo 11; the remainder must equal the tenth digit, and a remainder of 10 means the number is invalid. Source: https://polishdata.eu/validators/nip (consistent with every valid NIP in our tests). The plugin accepts dashes, spaces and a `PL` prefix, and reads a NIP typed into the billing company field ("Firma ABC, NIP 123-456-32-18").

## Cloudflare

- **Tunnel, created in the dashboard**: Networking, Tunnels, Create a tunnel; name it; choose the operating system and run the installation command it shows on the origin machine. Then on the tunnel: Routes tab, Add route, Published application, with Subdomain, Domain and Service URL (for example `http://localhost:8000`). The domain must be a website added to Cloudflare first. A path in the route "does not strip or rewrite the path": the service receives the complete request path (the signatures need exactly that). Source: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/get-started/create-remote-tunnel/
- **cloudflared on Windows** "installs itself as a system service", named `cloudflared` by default (settings under `HKLM\SYSTEM\CurrentControlSet\Services\cloudflared`, value `ImagePath`). Source: https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/run-parameters/
- **Access service tokens**: created in Zero Trust under Access controls, Service credentials, Service Tokens; the Client Secret is displayed only once; clients send `CF-Access-Client-Id` and `CF-Access-Client-Secret`; on a self-hosted application the policy action must be Service Auth, otherwise Access prompts for an identity provider login; a token expires after the duration chosen at creation and can be renewed. The plugin sends both headers when `cfAccessClientId` and `cfAccessClientSecret` are set. Source: https://developers.cloudflare.com/cloudflare-one/identity/service-tokens/

## .NET

- The bridge targets .NET 8 (`net8.0-windows` for the Sfera gateway, because the SDK loads WPF assemblies). The install script builds on the machine, so it needs the .NET 8 SDK, not only the runtime. Download: https://dotnet.microsoft.com/download/dotnet/8.0

## Medusa 2.15.3 (read in `node_modules/@medusajs/core-flows`)

- `upsertVariantPricesWorkflow({ variantPrices: [{ variant_id, product_id, prices }], previousVariantIds })`: updates the price set linked to each variant with `updatePriceSetsStep` (the pricing module replaces the prices of the set with the ones sent: prices not mentioned are deleted, so the writer sends every existing price back by id and changes only the target amount), and REMOVES the price set link of every variant in `previousVariantIds` that is not in `variantPrices`. The writer passes only the variant it updates.
- `batchPriceListPricesWorkflow({ data: { id, create, update, delete } })` for `priceTarget: "price_list"`.
- `createProductsWorkflow` with `status: draft`, one option ("Default option") and one variant: the product needs a sales channel and images from a person before it is published.
- `batchInventoryItemLevelsWorkflow` (stock) and `createOrderFulfillmentWorkflow` (`fulfillOnWz`) are unchanged since 0.1.0.
